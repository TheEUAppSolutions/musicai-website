## Phase 3: Free online splitter, feasibility sketch (⏳, needs a spending decision)

Searches like "vocal remover online" are answered by tools, not app pages. A page
that splits **the first 30 seconds** of an uploaded song in the browser, then hands
off to the app for the full song, is the biggest single lever. It is also the only
item in this plan that costs money to run.

**What exists** (MusicMastering_API):
- `POST /jobs` accepts a multipart upload.
- `htdemucs_6s` produces 6 stems.
- MP3/WAV output goes to the public `musicmastering` bucket.
- Results are cached by audio hash.
- It runs on GCE GPU VMs (L4 + T4) behind a global load balancer at `34.111.82.210`, over **plain HTTP**. The fleet costs about $750/month running 24/7.
- Separation takes roughly 4–6 s of L4 time per minute of audio, so a 30-second clip is about 2–3 s of GPU.

**What's missing for public web use:**
1. **A trim step.** The API has no start/duration parameter. Add `max_seconds` to
   `/jobs`, running ffmpeg `-t 30` before `process_job_sync`, or trim in the browser
   with the Web Audio API before upload. Server-side is safer, because the browser
   can't be trusted.
2. **A web gateway in front of the GPU API**, e.g. a small Cloud Run service at
   `api.musicaistudio.app`, HTTPS only:
   - Cloudflare Turnstile (free) on every upload.
   - A per-IP limit (for example 3 clips/day) and a global daily cap (for example
     500 clips/day), stored in Firestore or Redis.
   - File limit of 20 MB, audio only (checked with ffprobe).
   - Forwards to the GPU API with a server-side key.
   - The browser never calls the GPU fleet directly.
3. **Short-lived outputs.** Store web clips under `web/` with a 24-hour lifecycle
   rule, and serve them through signed URLs (`gcs_signed_url` already exists), not
   public URLs.
4. **Cost guardrails.**
   - A hard daily clip cap in the gateway.
   - The existing capacity 503 stays as a backstop. The gateway should show "busy,
     try the app" rather than queue.
   - A GCP budget alert.
   - Web jobs run at lower priority than app jobs.
   - Worst-case cost is roughly clip cap × 3 s of GPU. That fits inside the existing
     fleet's idle capacity, but *to validate* against real queue load before launch.
5. **Conversion.** The result page plays the 30-second stems in the same mixer UI,
   with "Get the whole song in the app" (campaign `ct=web-tool`), a QR code on
   desktop, and optionally the Web2Wave/Stripe web checkout already used by the
   `/stemsplit` promo flow.
6. **Legal.** An upload checkbox confirming the user has the rights to the audio;
   Terms and Privacy updated for web uploads (IP address for rate limiting, 24-hour
   retention).

**Blockers found while researching this (fix regardless of the web tool):**
- API auth is in log-only mode, so anyone can submit jobs.
- The app uploads over plain HTTP.
- Uploaded originals and stems sit in a public bucket.
- The internal dashboard (with a cache-clear endpoint) has no authentication.

The site's privacy text was corrected in this pass: it no longer says "encrypted
connection". Once the API is on HTTPS, that wording can come back.

## Phase 5: Localised pages (⏳)

Start with **es, pt-BR, de, fr**. The App Store already has es-MX, pt-BR, de-DE and
fr-FR listings, and the app UI is localised.

- **URLs:** `/es/`, `/pt-br/`, `/de/`, `/fr/`, each with the home page and the
  seven intent pages under a localised slug (e.g. `/es/quitar-voz-karaoke/`, *to
  validate* per language: translate the search intent, not the English slug).
- **hreflang:** every page lists all its language versions plus `x-default`:
  ```html
  <link rel="alternate" hreflang="en" href="https://musicaistudio.app/karaoke-maker/">
  <link rel="alternate" hreflang="es" href="https://musicaistudio.app/es/quitar-voz-karaoke/">
  <link rel="alternate" hreflang="pt-BR" href="https://musicaistudio.app/pt-br/fazer-karaoke/">
  <link rel="alternate" hreflang="de" href="https://musicaistudio.app/de/karaoke-erstellen/">
  <link rel="alternate" hreflang="fr" href="https://musicaistudio.app/fr/creer-karaoke/">
  <link rel="alternate" hreflang="x-default" href="https://musicaistudio.app/karaoke-maker/">
  ```
  The annotations must be reciprocal, and each page's canonical points to itself.
  Generate them from `intents.py` (add per-locale `slug`/copy dicts) so they can't
  drift. Add `<html lang>` per page, and link the App Store badge to the matching
  storefront.
- **Translation:** machine-draft with `Tools/AITranslate`, then have a native
  speaker review each page. Thin or garbled translations hurt more than they help.
- **Legal pages** stay English-only (with a note) unless counsel says otherwise.

## Phase 6: ASO, and how the site feeds it (⏳, needs the owner's decisions)

The website helps the App Store listing directly: install velocity from the web counts
toward ranking, and Search Console shows which words people use. That feeds keyword
choices, and the store listing's words feed the page titles.

**Live listing audit** (read via the ASC API on 2026-09-25, version 1.5.3):

| Locale | Name | Subtitle | Problems seen |
|---|---|---|---|
| en-US | Stem Split - AI Vocal Remover | Voice isolation. Extract Music | Keywords spend space on *station, tune, changer, beat, maker*. The name already covers *vocal remover*. |
| en-GB | Stem Split AI - Vocal Remover | Make your own Music & Songs | The subtitle implies music creation (misleading). Keywords include *mixr, generator*. |
| de-DE | Stem Split - Lieder schneiden | Audio & Music Editor & Maker | *koala*, and English words mixed into German keywords. |
| es-MX | Stem Split - Mixing Station | Editor de Audio y Música | The name has no "vocal remover" equivalent. Keywords include *suno*, a competitor brand (risky). |
| fr-FR | Stem Split - Vocal Remover | Banger karaoke music & chord | The subtitle is English slang on a French listing. *ringtones* and *accordeur* are off-intent. Duplicate *piano*. |
| pt-BR | Stem Split - Mixing Station | sua aplicativo de musica | Grammar ("sua aplicativo" should be "seu aplicativo"). *reverse, funk, brasil* are off-intent. |
| ja / ko | — | — | Several unrelated keywords (e.g. alarm-sound maker, sanshin tuner in ja). |

**Recommendations:**
- Align each locale's **name + subtitle** with the site's top intents: vocal remover,
  karaoke, stem splitter, isolate instruments, chords.
- Clear competitor brand names out of the keyword fields (App Review can reject
  them).
- Don't repeat words that already appear in the name or subtitle. Apple indexes
  those anyway.
- Use the page titles that earn Search Console clicks as input for keyword choices,
  and vice versa.
- The App Store screenshots still show the old BETA pill. Re-shoot them from the
  current build once `video_beta_badge_enabled` is decided.
- Any listing change goes through `deploy.sh MusicMastering metadata` and ships with
  the next version. **Owner approval required: nothing was changed.**
